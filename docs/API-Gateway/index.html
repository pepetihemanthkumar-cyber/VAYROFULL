DriveEase — API Gateway

Centralized Routing, Security, Rate Limiting, and Service Discovery Architecture

⚠️ Academic Architecture Disclaimer:
This page presents the planned API Gateway configuration and security architecture for the DriveEase microservice backend. The current DriveEase React application operates as a standalone frontend with local browser storage. The production API Gateway will be deployed during the backend microservices integration phase.

1. What is an API Gateway?

An API Gateway is a reverse-proxy server acting as the single, centralized entry point for all client traffic entering backend microservices.

2. Direct Access vs. API Gateway Architecture

Comparing direct client-to-service access against a centralized Gateway pattern.

WITHOUT GATEWAY (Direct Access)
  • ✗ Client manages 7+ individual service IP/URL endpoints.
  • ✗ CORS headers must be configured on all 7 services.
  • ✗ JWT signature verification code duplicated across services.
  • ✗ Internal microservice ports exposed to public internet.
  • ✗ Inconsistent error codes and client coupling.
WITH GATEWAY (Centralized)
  • ✓ Single client URL (`https://api.driveease.com`).
  • ✓ CORS headers managed centrally in one location.
  • ✓ JWT verified once statelessly at Gateway edge.
  • ✓ Microservices isolated on private VPC network.
  • ✓ Centralized rate limiting, logging, & correlation IDs.

3. Complete API Gateway Architecture

Centralized filters, rate limiters, service discovery lookups, and microservice routing.

1. JWT Security Filter

Statelessly verifies RS256 token signatures and role claims (`CUSTOMER` vs `ADMIN`) before forwarding requests.

2. Redis Rate Limiter

Token bucket algorithm caps request volume per IP to prevent brute-force attacks (`429 Too Many Requests`).

3. Eureka Service Lookup

Queries discovery registry dynamically to find healthy IP instances (`BOOKING-SERVICE` -> `10.0.1.48:8084`).

7. Gateway Degradation & Failure Handling

Failure Scenario Gateway Detection Gateway Action & Response
Vehicle Service Down Eureka status `DOWN` or connection refused. Returns 503 Service Unavailable with clean JSON error.
Booking Service Slow Response time exceeds 2000ms threshold. Cancels request and returns 504 Gateway Timeout.
Invalid JWT Token Signature or expiration check fails. Returns 401 Unauthorized before touching microservices.
Rate Limit Exceeded Redis token count reaches 0. Returns 429 Too Many Requests with `Retry-After: 60`.

8. Viva & Evaluation Quick Guide

Key questions a faculty evaluator may ask about API Gateway in DriveEase.

Q1: Explain API Gateway in 60 seconds.
"An API Gateway is the single entry point between the DriveEase React frontend and backend microservices. It receives all client requests, enforces centralized security—such as verifying JWT token signatures using public key cryptography—applies rate limiting and CORS policies, performs dynamic service discovery lookups via Eureka, and routes requests to the appropriate healthy microservice instance. By encapsulating internal microservice endpoints inside a private network, the API Gateway protects downstream services, simplifies client integration, and enables independent scaling."
Q2: How does the Gateway handle authentication statelessly?
It intercepts incoming Bearer tokens and verifies the RS256 cryptographic signature using the Auth Service's public key without querying the database on every HTTP request.
Q3: What happens when an unauthenticated customer tries to call an Admin route?
The Gateway inspects the token claims, detects that the user role (`CUSTOMER`) does not match the required `ADMIN` role policy, and halts execution immediately by returning HTTP 403 Forbidden.
Q4: Why should internal microservices not be directly accessible to clients?
Direct exposure bypasses Gateway security filters, increases attack surface, exposes internal IP infrastructure, and complicates client routing logic.
